# Acessibilidade — Soul DS

> Esta página cobre o que é **transversal** (vale para qualquer componente).
> A nota de acessibilidade específica de cada componente já está em
> `data/components.json → <componente>.a11y` — não repetida aqui.
> `validate.mjs` automatiza 5 das checagens abaixo; as demais exigem revisão manual.

---

## O que `validate.mjs` já checa automaticamente

Não repita manualmente o que o validador já cobre — rode
`node scripts/validate.mjs <arquivo>` antes de revisar à mão:

- Botão icon-only sem `aria-label`
- Ícone decorativo sem `aria-hidden="true"`
- Ícone com `role="img"` sem `aria-label`
- `<input>` sem `<label for>` nem `aria-label`
- SVG inline com cor hardcoded (deveria ser `currentColor`)

## O que precisa de revisão manual

### Foco (2.4.7)

Nenhum componente do Figma tem `state=focus` no enum — só o CSS
implementa `:focus-visible`. Isso significa que o Figma não consegue ser
a fonte de verdade para foco: a implementação é sempre a referência.

`validate.mjs` **não** detecta `outline: none` sem substituto — verificar
manualmente que todo elemento interativo tem um indicador de foco visível
equivalente ao padrão global de `tokens.css`:
```css
:focus-visible { outline: var(--border-width-2) solid var(--color-ring); outline-offset: 2px; }
```

Atenção especial nos temas Green: `--color-ring` mede 2.88:1 de contraste
contra o fundo (alvo 3:1) — ver `rules.json → contrasteConhecido`. O foco
existe, mas é visualmente insuficiente nesses dois temas.

### Padrões ARIA não modelados no Figma

Estes componentes precisam de semântica que nenhuma Diretriz do Figma
documenta — a implementação é responsável por adicionar:

| Componente | O que adicionar | Por quê |
|---|---|---|
| `switch` | `role="switch"` + `aria-checked` | Figma só documenta `selected` como boolean visual |
| `aba` | `role="tablist"` no container + `role="tab"` no item + `role="tabpanel"` no conteúdo | Padrão de navegação por teclado (setas) não é modelável em variant do Figma |
| `dialog` | `<dialog>` nativo com `showModal()` para focus trap | Sem isso, foco escapa do modal — 2.1.2 |
| `breadcrumb` | `<nav aria-label="breadcrumb"><ol>` envolvendo os itens | Estrutura de lista, não só os itens soltos |
| `sidebar` (`codeOnly`) | `<nav aria-label="lateral">` envolvendo | Presente no HTML de exemplo, ausente do CSS |
| `calendario` | Navegação por teclado entre dias (setas) | Não documentado no Figma, WCAG 2.1.1 |

### Contraste — não confie só na paleta

`data/rules.json → contrasteConhecido` lista as razões já medidas contra
os valores reais. Resumo dos que falham hoje:

| Token | Contraste | Alvo | Onde dói |
|---|---|---|---|
| `--color-muted-foreground` | 2.36:1 | 4.5:1 | Helper text, placeholder, caption, header de tabela — o token mais usado do sistema |
| `--color-border` | 1.39:1 | 3:1 | Borda de input praticamente invisível |
| `--color-info` em `--color-info-background` | 3.88:1 | 4.5:1 | `.alert--info` |
| `--color-success`/`--color-warning` em seus `-background` | 4.18:1 / 4.42:1 | 4.5:1 | Mais perto após a correção da Fase 4, ainda abaixo |
| `--color-ring` nos temas Green | 2.88:1 | 3:1 | Foco visualmente insuficiente |

Nenhum destes tem correção automática — são decisões de paleta que
precisam de um ADR de cor separado (ainda não aberto, ver `TOK-2`/`TOK-3`
no manifesto).

### Cor como único diferenciador (1.4.1)

`alert` e `badge` (ambos `codeOnly`) distinguem `variant` **só por cor**
— sem ícone por tipo. A coleção `mv-basico/alerta` já tem `erro`, `aviso`,
`alerta`, `ajuda` prontos para resolver isso (resolvíveis via
`find-icon.mjs`), mas nenhum dos dois componentes os usa hoje.

### Tamanho de alvo de toque (2.5.8, WCAG 2.2)

Mínimo recomendado 24×24px. `check`/`radio` em `size=sm` (16px) provavelmente
ficam abaixo disso sem área de toque estendida via padding — testar com
ferramenta de medição antes de usar `size=sm` em contexto touch.

## Princípio geral

Ícone decorativo: `aria-hidden="true"`. Ícone com significado: `role="img"`
+ `aria-label"`. Botão sem texto: `aria-label` no `<button>`, nunca no
ícone dentro dele. Isso já é checado automaticamente — o objetivo desta
seção é só deixar o princípio explícito para quando `validate.mjs` não
alcança (composição, não sintaxe).
